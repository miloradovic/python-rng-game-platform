# Migration policy

Alembic migrations are the only supported database schema-change mechanism. Run
Alembic through the `app` Compose service; do not invoke host Python or edit a
database schema manually.

Before accepting an autogenerated migration, verify:

- every operation corresponds to an intended SQLAlchemy metadata change;
- durable invariants have database constraints, foreign keys, and useful indexes;
- existing data remains valid and forward migration is safe;
- downgrade behavior is accurate and does not silently lose data;
- table, constraint, and index names are stable and reviewable;
- no gameplay seed data or hidden startup initialization appears in the revision;
- upgrade, downgrade, and restoration to head pass against real PostgreSQL.

Destructive or irreversible product migrations require explicit user approval and
a documented data migration plan. Seed rows belong in `tools.seed`, remain
repeatable, and are never coupled to schema migration.
